# Contract corrections and compact mobile details

Contract edits now return the saved draft in the full read projection. Reopened forms retain the submitted rate, fees, drivers and other details. Live rates, deposits and dates also override outdated snapshots. Contract customer corrections take precedence over linked directory values, including intentional empty values. Manual amounts are no longer overwritten by automatic pricing while editing an issued contract.

The correction endpoint no longer enforces issuance prerequisites: ready/branch stock, scheduling conflicts, Telegram state, complete customer identity/contact information, active commission staff, renewal boundaries or stale form versions. Corrections use the latest locked order and retain before/after audit data. Empty date/vehicle fields can be saved and reopened. Authorization and database-compatible value types remain enforced. The draft/final-issuance workflow keeps its existing behavior.

Vehicle, customer, store, contract and expandable detail cards use two columns below 480px and three columns from 480–768px. Names receive two cells; addresses and notes span the row. Existing forms keep their layout. Mobile footer actions have a 44px minimum touch height.

Mobile dialogs include Back / Home / Load inside the native modal layer. Back closes the current dialog, Home opens the permitted home page, and Load uses the existing data refresh. The dialog reserves bottom space for these controls, including fullscreen dialogs; desktop presentation is unchanged.

Validation: production build, TypeScript, changed-file ESLint, contract edit/API checks, rollback PostgreSQL fixtures using the actual production draft projection, and Chrome layout checks at 320/393/600/1024px. Headless UI fixtures render the real vehicle component with synthetic data and management CSS; no network or business writes. Screenshots generated by `node scripts/check-mobile-detail-columns.cjs`.
