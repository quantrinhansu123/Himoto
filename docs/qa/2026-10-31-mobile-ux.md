# Mobile UX refinement — 31/10/2026

The user requested practical, readable and stable daily-work screens. The
overall app goal is active; this UX checkpoint does not complete the product.

## Implemented

- Compact overview: user/store context, readable counts and direct shortcuts to
  ready vehicles, overdue contracts and saved drafts. No extra summary queries
  are needed merely to render the shortcut buttons.
- Search and quick filters stay above the virtualized list while scrolling.
  Landscape uses a compact toolbar so the list remains usable.
- A complete filter sheet stages status/store choices until Apply. Closing it
  preserves the current list. Store names can be searched without accents.
- All business statuses can be selected, with contextual labels for pending
  handover contracts and incomplete customer profiles.
- Empty results offer a reset action. A failed next-page request preserves
  loaded records and exposes an explicit retry rather than automatic loops.
- Details show the vehicle name, a contextual header and a call action for a
  valid phone number. Refresh failure preserves the last loaded record with a
  visible stale-data message.
- Selected/busy/disabled state props work in native and web rendering. Tab-bar
  height grows for larger system text. Modal motion respects Reduced Motion.
- Control boundaries have separate color tokens from decorative card borders.
  Automated checks cover 4.5:1 text contrast and 3:1 control-boundary contrast in
  light/dark themes, without claiming native screen-reader certification.

## Android native build

An Android project was generated using `expo prebuild --platform android
--no-install`, preserving Continuous Native Generation. The local Gradle build
uses the installed Android SDK/JBR; its first run downloaded Gradle 9.4.1 and is
compiled native plugins. An Android emulator booted successfully in read-only,
headless mode, then was stopped to free memory during the build on this 8-GB
host.

The first Gradle run failed when a Java compile worker could not connect within
120 seconds under memory pressure. A retry uses one worker, disables parallel
projects and runs the Kotlin compiler in process, with a 1280-MB Gradle heap.
That retry passed Java/Kotlin compilation and reached native C++ compilation,
then failed on Ninja 1.10.2's Windows 260-character path limit in Gesture Handler
codegen. Windows already has long paths enabled. Android SDK CMake 3.31.6/Ninja
1.12.1 was installed and selected with `-Pandroid.cmakeVersion=3.31.6`; the next
run uses a 512-MB Metaspace limit. Gradle runs one task at a time, but Ninja can
still launch multiple C++ compiler processes. These failures
are not evidence of a completed native build.

The subsequent CMake 3.31.6 run completed successfully: `BUILD SUCCESSFUL in
10m 11s`, 483 tasks (45 executed, 438 up-to-date). Its x86_64 debug APK is
`mobile/android/app/build/outputs/apk/debug/app-debug.apk`, 95,784,616 bytes.
